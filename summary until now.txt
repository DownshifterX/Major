1. EXECUTIVE OVERVIEW
--------------------------------------------------------------------------------
Nya(AI) is a full-stack legal intelligence and decision-support platform designed
for advocates, legal researchers, clerks, and scholars. It addresses the 
fundamental flaws of general-purpose LLMs in law (hallucinated citations, lack of
jurisprudential grounding, opaque recommendations) through a hybrid search 
engine, multi-signal legal reranker, canonical legal structure parser, and 
deterministic zero-hallucination citation provenance.

The repository transitioned from a baseline concept (v1) into a production-ready, 
modular v2 architecture backed by real Indian legal judgment datasets.

2. WHAT HAS BEEN DONE (DELIVERABLES & ACHIEVEMENTS)
--------------------------------------------------------------------------------

A. Real Indian Precedent Corpus & Ingestion Pipeline:
   - Ingested 130 landmark Indian court decisions (including landmark precedents 
     like Kesavananda Bharati, Maneka Gandhi, Bachan Singh, Siddharam Mhetre) 
     from parquet/excel datasets containing ~12,000 court judgments.
   - Built an automated ingestion pipeline (ingest_dataset.py) that cleans legal 
     texts, chunks judgments by legal paragraphs/sections, computes embeddings, 
     and indexes 10,949 judgment chunks into SQLite (nya.db).
   - Extracted and structured 7,984 citation edges connecting historical 
     cases into a citation network.

B. Multi-Signal Precedent Reranking Engine:
   - Designed and implemented a legal-specific reranking system (reranker.py) that 
     combines five distinct signals with weighted authority:
       1. Semantic Similarity: Dense vector distance (BERT/SentenceTransformers).
       2. Lexical Relevance: BM25 exact match on query terminology.
       3. Statutory Overlap: Direct intersection with cited Acts & Sections 
          (e.g., IPC, CrPC, Evidence Act, Constitution).
       4. Citation Graph Authority: PageRank and in-degree citation count.
       5. Judicial Hierarchy: Weight favoring Supreme Court over High Courts.
   - Outputs transparent scoring breakdown cards explaining why each precedent 
     was recommended.

C. Citation Graph Network Analytics:
   - Built citation graph analytics (citation_graph.py) using NetworkX.
   - Computes PageRank centrality, in-degree/out-degree counts, and shortest 
     precedent citation paths.
   - Enables graph-based precedent discovery and network inspection via REST API.

D. Canonical Legal Structure & Section Extractor:
   - Developed rule-based legal structure extractor (legal_structure.py) with 
     specialized regex & heuristic patterns for Indian court judgments.
   - Automatically segments unstructured judgments/pleadings into:
       * Facts of the case
       * Issues framed
       * Petitioner arguments vs Respondent arguments
       * Judicial reasoning
       * Final holding / decision
       * Statutory provisions & sections cited

E. Automated Document Ingestion & Web Scraping:
   - Added automated document acquisition (document_acquisition.py) capable of:
       * Scraping judgments directly from Indian Kanoon URLs with user-agent 
         rotation and exponential backoff.
       * Ingesting uploaded files in multiple formats (.pdf, .docx, .txt, .md).
       * Legal text sanitization (text_cleaner.py) removing boilerplate court 
         headers, line artifacts, and formatting noise.

F. Zero-Hallucination Legal Analysis & Orchestration:
   - Implemented analysis orchestrator (analysis_service.py) connecting 
     retrieval, structural extraction, and LLM synthesis.
   - Strict citation discipline: Every generated statement, argument, or summary 
     carries verifiable citation chips ([S1], [S2]) mapped directly to exact 
     source judgment chunks with character offsets.
   - Supports pluggable LLM backends (Anthropic Claude API or grounded mock 
     deterministic legal NLP provider).
   - Generates Pre-Hearing Briefs, prosecution vs. defence argument matrices, 
     evidence gaps, and contradiction reports.

G. Unified 1-Click Platform Launcher:
   - Created run.py, a zero-friction master launch script that:
       * Verifies Python environment and dependencies.
       * Checks/initializes the database schema and indexes.
       * Starts the Uvicorn ASGI server on port 8000.
       * Automatically opens the browser to http://127.0.0.1:8000.
       * Supports CLI arguments (--port, --host, --no-browser, --reload).

H. Modern Web Frontend:
   - Built a sleek, dark-themed Single-Page Application (HTML5, Vanilla CSS, JS).
   - Features:
       * Legal Research Search tab with real-time Semantic, BM25, and Hybrid scores.
       * Case registration modal supporting manual entry or Indian Kanoon URL scraping.
       * Document management panel with file upload and live indexing status.
       * Interactive analysis dashboard: Similar Cases, Reranked Precedents, 
         Legal Provisions, Prosecution vs Defence, Evidence Gaps, Contradictions, 
         Case Comparison Matrix, and Court Brief export.

I. Testing, Quality Assurance & Benchmarks:
   - 28 automated unit and integration tests (test_v2.py, test_api_integration.py) 
     verifying endpoints, SQLite concurrency, database models, and retrieval.
   - Quantitative evaluation script (evaluate.py) measuring:

3. HOW IT WAS DONE (METHODOLOGY & ARCHITECTURAL IMPLEMENTATION)
--------------------------------------------------------------------------------

Layer 1: Data Architecture & Persistence
   - Database: SQLite (nya.db) via SQLAlchemy ORM (compatible with PostgreSQL).
   - Models:
       * Case: Active user workspaces and case metadata.
       * Document: Uploaded or scraped case documents.
       * Chunk: Paragraph-chunked text blocks with embeddings and metadata.
       * HistoricalCase: 130 indexed Supreme Court & High Court judgments.
       * Citation: Directed edges recording precedent citation linkages.

Layer 2: Hybrid Retrieval & Search Pipeline
   - Dense Embeddings:
       * SentenceTransformers (sentence-transformers/all-MiniLM-L6-v2, 384 dimensions)
         or deterministic hash fallback.
       * Fast in-memory cosine similarity matrix calculation.
   - Lexical Search:
       * BM25 algorithm prioritizing legal keywords, statutory citations, and sections.
   - Hybrid Fusion:
       * Linear interpolation: Hybrid Score = alpha * Dense + (1 - alpha) * BM25.

Layer 3: Precedent Scoring & Reranking Mathematics
   - The multi-signal reranker scores candidate precedents using:
       Total Score = (w_sem * Sim_sem) +
                     (w_bm25 * Sim_bm25) +
                     (w_statute * Overlap_statutes) +
                     (w_cite * PageRank_centrality) +
                     (w_court * Hierarchy_weight)
   - Guarantees top-ranked precedents are both conceptually relevant to facts and 
     judicially authoritative in Indian courts.

Layer 4: Backend REST API (FastAPI)
   - Modular routers:
       * /cases: Case workspace lifecycle.
       * /documents: File upload, scraping, and chunking.
       * /historical-cases: Precedent browsing and query.
       * /analyze & sub-routes: Full analysis, similar cases, reranked precedents, 
         arguments, contradictions, comparisons, and briefs.
       * /api/search: Fast legal research search.

Layer 5: Presentation & User Experience (Frontend)
   - Zero-build architecture (pure HTML5, CSS3, JavaScript ES6) serving static 
     assets straight from FastAPI.
   - Styled with clean glassmorphic components, high-contrast dark theme, and 
     responsive tab routing.
